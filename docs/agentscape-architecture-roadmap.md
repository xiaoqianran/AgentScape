# AgentScape 长期架构决策与演进锚点

状态：已批准，阶段 0 实施中

本文记录 AgentScape 作为 Three.js 可选能力层的长期方向。它与[原生 Three.js 注入架构契约](native-threejs-architecture.md)、[原生 Three.js 集成指南](native-threejs-integration.md)和[交互式世界运行时架构](interactive-world-runtime-architecture.md)共同构成架构基线。

## 产品定位

AgentScape 面向已经拥有 Three.js 世界的开发者，提供对象身份、语义、交互动作、物理协调、空间查询和可验证结果。宿主项目继续拥有自己的 Scene、Camera、Renderer、Composer、材质、灯光、Shader、动画和资源生命周期。

AgentScape 也保留自管世界模式。原生接入模式与自管世界模式共享实体、动作和证据契约，分别遵守各自的场景和资源所有权边界。

近期产品验收以一个真实 GLB 场景为准。开发者加载柜子和杯子，为部件登记语义与物理能力，Agent 能发现对象、打开柜门、取放杯子，并返回可检查的状态和证据。

## 三个长期边界

### 原生边界

模块导入和显式接入不得修改 Three.js 全局原型，不得替换宿主 renderer，不得偷偷建立第二套渲染循环。宿主 renderer 的观测属于可选诊断能力，必须显式启用并支持释放。

AgentScape 创建并拥有的对象可以启用对象级优化。当前 BVH 实现通过对象实例上的 `raycast` 和几何上的私有 `boundsTree` 工作，不向 `Mesh.prototype` 或 `BufferGeometry.prototype` 写入方法。宿主对象默认不进入这条路径，宿主自定义 `raycast` 也必须保留。

### 权限边界

绑定对象只获得调用方明确登记的能力。语义、物理、导航、音频、乐器、生成和动作执行分别登记，不能通过扫描全部 Mesh 猜测出隐含权限。

宿主直接修改对象变换时，非侵入式接入无法阻止外部写入。AgentScape 只约束自己的写入，并在可观测时报告宿主、动画和物理之间的控制权冲突。

### 证据边界

动作被接受、动作回调完成、目标状态改变和物理结果成立是不同状态。公开结果必须区分物理证据、世界状态证据、宿主报告和项目自定义证据。

## 推荐运行模式

| 模式 | 场景与渲染所有权 | 时钟 | 适用范围 |
| --- | --- | --- | --- |
| Native Host | 宿主拥有 | 宿主调用 `frame()`，或显式选择运行时 RAF | 已有 Three.js 项目 |
| Managed World | AgentScape 拥有 | AgentScape 管理 | 独立世界、Studio、MCP 和无宿主场景 |

新接入项目推荐宿主驱动模式。当前 `autoStart: true` 为兼容既有调用保留，后续若调整默认值必须通过版本和迁移说明完成。

同一批需要相互碰撞的对象只能有一个权威物理世界。宿主已有 Rapier 或其他物理系统时，优先通过适配器接入。无法提供某项能力时返回不可用状态，不能通过并行求解器假装实现双向同步。

## 稳定身份

运行时实体 ID 标识场景实例中的对象。资产版本使用资产 ID 与内容哈希。GLB 部件使用由资产作者或侧车 Manifest 维护的稳定部件 ID。当前 `Object3D` 只作为运行态引用。

同一 GLB 多次实例化时，每个实例拥有独立实体 ID，可以共享资产版本和部件定义。节点名称用于展示和辅助匹配，不能单独承担跨版本身份。模型结构变化导致映射无法确认时，恢复必须报告失败并要求重新映射。

## 能力装配顺序

```text
发现对象 → 登记身份 → 登记语义 → 编译物理与空间能力
→ 登记动作与控制权 → 执行动作 → 收集证据 → 发布结果
```

生成对象遵循以下闭环。

```text
目标位置 → 生成或导入 GLB → 隔离预览 → 编译和验证
→ 重新检查世界版本与空间 → 原子提交 → 进入交互运行时
```

预览、取消、重试和并发提交必须拥有请求身份和幂等键。外部生成服务的副作用只能记录和补偿，世界内部的实体、能力和资源提交才属于 AgentScape 可控制的事务范围。

## 路线决策

保留现有 `WorldRuntime`、`SceneFacade`、`NativeSceneHost` 和实体能力注册表，不推倒重来。优先把原生边界、资源所有权、时钟、变换控制权和物理权威落实为代码和测试，再扩展生成、音频、多人和大型世界。

不采用完整替代 Three.js 的路线，因为它会重复实现渲染和资源生态。不采用只登记语义的极薄 SDK，因为真实交互和结果验证会退回到每个宿主自行实现。采用按需装配的能力运行时，Studio、MCP 和生成服务都是入口或可选能力，不是原生接入前置条件。

## 分阶段验收

| 阶段 | 主要交付 | 退出条件 |
| --- | --- | --- |
| 0 | 消除全局副作用，固定对象级 BVH、释放和类型边界 | 原型身份、宿主自定义 raycast、共享几何、失败清理和独立消费者测试通过 |
| 1 | 时钟与 Transform Authority | 宿主动画、运动学、动态物理、控制权切换、解绑和重复关闭通过 |
| 2 | 真实 GLB 交互闭环 | 多实例身份、部件映射、关节动作和物理结果可验证 |
| 3 | 宿主物理适配 | 一个真实已有物理世界完成同世界碰撞和动作验证 |
| 4 | 实时生成入场 | 预览、取消、重试、冲突、幂等提交和资源清理通过 |
| 5 | 生态扩展 | Three.js 版本、R3F、后处理、WebGPU、XR 和大型世界都有独立测试结果 |

每项兼容声明都必须对应测试和示例。静态图谱中的高耦合数量用于定位调查范围，不能直接作为软件缺陷结论。

## 当前实施记录

2026 年 11 月 20 日，阶段 0 已移除 WorldRuntime 导入时的全局 BVH 原型安装。`ensureBoundsTrees()` 现在只为进入 AgentScape 自有空间查询的对象构建几何树，并以对象实例方式启用加速射线。释放会恢复对象原有的 `raycast`，并释放私有几何树。

当前提交已验证以下结果。

- 导入 NativeSceneHost 不改变 `Mesh.prototype.raycast`。
- 导入 NativeSceneHost 不改变 `BufferGeometry.prototype.computeBoundsTree` 和 `disposeBoundsTree`。
- 自有 Mesh 可以启用并释放对象级 BVH。
- 宿主自定义 `raycast` 不会被覆盖。
- 原生场景相关集成测试和世界资源释放测试通过。

完整测试矩阵、浏览器矩阵、发布包入口和 WebGPU、XR、R3F 专项仍需按阶段补齐后再扩大兼容承诺。
