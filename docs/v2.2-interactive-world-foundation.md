# AgentScape v2.2 — Interactive World Foundation（第一批）

状态：开发中；本文记录已经实现的范围与仍未满足的门槛，不是 npm 发布声明。

## 设计原则

- **唯一事实源**：Runtime 的 ObjectStore、WorldAffordances 和 Environment 仍持有实际状态；Studio、SDK、MCP 不保存第二份可写对象。
- **区分身份与能力**：Environment 自身、具有正式 Runtime 身份的资产、环境原生交互点、纯视觉 Mesh 是不同概念。不能因为画面中存在 Mesh 就称其可编辑、可碰撞或可由 AI 操作。
- **执行与验证分离**：动画激活不等于物理关节运动经过验收。只有 Runtime 返回正式验证证据时才能报告为 verified。
- **不扩建新的执行链**：继续使用 SceneFacade、WorldCommands、WorldAffordances、AssetModule 与现有 MCP Scene 工具，不新增平行 Runtime 或 Docker 依赖。

## 本阶段变更

### 1. 统一内置世界目录

- `modules/world/content/environments.js` 提供 `BUILTIN_ENVIRONMENT_IDS` 和严格的 `findEnvironment()`。
- `SceneProject` 的环境 ID 从同一目录校验；已删除的世界和未知环境会产生 `INVALID_DOCUMENT`，不会静默切到纪念大厅。
- `SceneFacade.openScene()` 从目录懒加载工厂，不再硬编码圆明园和纪念大厅；浏览器专属、依赖 DOM 的魔女小屋在无 DOM 的 Node SDK 中明确返回 `ENVIRONMENT_REQUIRES_BROWSER`。
- Studio 首页默认环境继续为 `suzhou-garden`；SDK 默认仍是兼容性稳定的 `monument-hall`。两者默认值不同，不代表可使用的环境目录不同。
- Scene API 的项目 `objects` 是显式声明的实体集合。仅指定一个内置环境不会自动注入 Studio 的预置家具/交互资产；Studio 的 `bootstrap` 是单独的内容模板，而不是 Scene Project 的隐式副作用。

### 2. 场景原生交互点

- Studio 场景树新增「场景交互点」分区，仅从 Environment `interactions` 中投影具有稳定 ID 和 Object3D 的条目；不把任意 Mesh 当作 Runtime 实体。
- 正式 `contractId` 作为可选中对象的身份，沿用已有 Inspector 与 WorldAffordances 操作；原生无契约条目仍走已有 LegacyAction。
- 同一 `contractId` 不重复显示。列表一次展示最多 100 项，可通过搜索过滤其他项目；它是只读视图，不复制世界状态。
- Scene `observe({actor})` 增加 `nativeInteractions`：返回数量和至多 100 个交互点的名称、位置、原生/契约区分及验证级别。
- Scene `interact({action:'activate',actor,target})` 针对原生 **interaction.id**，只允许实际 Agent 身份，复用 `WorldCommands.activateEnvironmentInteraction()` 的距离、遮挡和状态校验。激活成功但只有原生动画证据时：Job `succeeded`、Verification `unverified`、`physicsVerified:false`。阻挡或交互不存在时不会宣称成功。

正式契约交互（例如带物理铰链的门）应继续先 `inspect(target,{actor})`，再 `interact({action:'open',actor,target,partName})`，以 Runtime 验证结果为准。新增的 `activate` **不替代** 已经可验证的物理动作。

### 3. 端到端回归

- Scene Project 接受完整目录，明确拒绝移除的良渚世界、未知世界。
- 分别打开并保存 industrial-cabinet-lab、suzhou-garden，确认实际加载的 Environment ID 一致；已移除的 blank-world、house-world、house-door-world 必须被 Scene API 拒绝。
- 物理交互工作流：在保留的工业储物柜实验室验证 Agent 操作关节、导出世界包、重开并检查交互身份。
- 原生交互：观察到原生开关、近距激活后标记未验证、远距拒绝、虚假 Agent 拒绝。
- Studio 场景树读模型：合同身份去重、环境 / Runtime 同名 ID 不混淆、仅投影可选择的交互条目。

## 未完成，不得称为已实现

1. 所有大型世界的逐建筑碰撞体、导航网格和交互语义尚未完成；苏州园林目前仍主要是高精度视觉环境加简化地面代理。
2. 尚未对复杂世界做人工画质审核、真实 GPU 帧率、长时间内存/资源释放压力测试。
3. 需要继续做首次独立人类用户体验验收及候选发布提交的托管 CI，不能将本地 Vitest / Chromium 结果作为替代。
4. v2.2 尚不是正式发布版本；不得自动 npm publish、创建发布标签或声称所有 Scene 内容都通过物理验收。
