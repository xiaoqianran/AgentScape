# 柜内杯子放到桌面：内置资产验收

这项标准任务使用现有 WorldIR → WorldBuilder → SkillRegistry → WorldRuntime 链路，不需要在线模型和生成服务。正常场景共九次执行及四种故障的结果见 [本轮阶段报告](../evidence/cabinet-cup-2026-11-02.json)。这证明固定工具选择下的真实运行时闭环，不是实际 LLM 的成功率。

## 准备与用户入口

`application/tasks/CabinetCupTask.js` 提供 `createCabinetCupTaskWorldIR(worldId)`。把结果交给已有 `WorldBuilder.run` 或已授权的世界构建流水线，不能用测试脚本中的坐标移动替代动作。

`inspectCabinetCupTask(runtime)` 只读检查真实对象引用、开门和拿放能力、柜内容器、桌面、杯子当前包含关系及合法可达交互位置。返回 `{supported, refs, stages, reasons}`；缺目标或不可达时给出具体原因。这是初始场景检查，不能用来承诺后续没有动态障碍。重试时保留世界当前状态并重新观察，不能为了满足初始条件把杯子搬回柜子。

| 环境 | 标准任务布局 | 本轮结果 | 限制 |
| --- | --- | --- | --- |
| 纪念大厅 | 已有 bootstrap 智能体／柜子／桌子位置，杯子通过 INSIDE 关系编译放入柜内 | 3/3 正常执行通过 | 普通 bootstrap 杯子在桌上，不满足柜内取杯前提 |
| 林间工坊 | 已有 composer 自动安排智能体、柜子、桌子，杯子 INSIDE | 3/3 正常执行通过 | 普通声明出生位置与场景相交；标准场景不使用此位置 |
| 魔女小屋 | 已有户外 bootstrap 智能体／柜子／桌子位置，杯子 INSIDE | 3/3 正常执行通过 | 柜子与智能体都在户外，屋内出生且大门关闭时不能到达 |
| 遗迹庭院 | 未支持此标准任务 | 本轮历史实验 auto 布局失败 | 禁止把所有内置世界标成支持 |
| 大型城市街区 | 未验收此标准任务 | 未运行 | 其他导航验收不等于柜内取杯验收 |

三种支持布局的构建准入仍为 `provisional`（柜门资产准入或布局证据未全部 ready）；真实交互的 `world-accepted` 不改变这项结论。

## 修复与证明

原柜内区域底面为 y=0.15，真实底板碰撞体顶面为 y=0.10。杯子生成时在区域内，静置后落在底板上反而被判为区域外。现将容器底面与真实底板顶面对应，顶面保持 y=1.80；不改变碰撞体、物理容差和支撑验证器。

每次执行分别记录构建、初始静置、前置检查、开门、拿取、搬运放置和验证阶段。检查生成及静置 90 帧后都在柜内、拿取建立真实 held ownership、放置必须 `supportVerified && settled`，再推进 90 帧独立核验 ON 关系和空手。每个环境在同一个 Runtime 中重建三次，成功不能依靠上一次的交互证据。

故障样本保留阶段结果并停止：

- 删除杯子：前置检查准确报缺失，不启动动作。
- 柜门真实物理阻挡：得到 `action-failed / STALL`，不继续拿取。
- 桌面被真实物理障碍占用：放置无法找到合法交互位置，保留杯子的 held ownership，不释放或宣称成功。
- 小屋智能体位于屋内、目标在屋外且大门关闭：前置检查报无可达交互位置，不启动动作。

这些是定向故障样本，不保证覆盖任意障碍布局或所有恢复策略。当前采用可解释地停止；不为提高通过率添加无限重试。

## 运行

```sh
npm ci
npm run acceptance:world
npm exec vitest run tests/e2e/cabinet-cup-acceptance.test.js
```

完整报告默认输出 `.tmp/cabinet-cup-acceptance.json`，包含所有尝试、工具执行和后置条件。CLI 任一用例不符合预期即非零退出；测试是默认 Vitest 的一部分。报告中的固定 gateway 必须保持明确标签。

本轮也重跑了 `003`、`004`、`005`。原默认布局的准入拒绝和小屋门的导航分区仍可复现；004 出现“新一次构建被拒绝但仍操作上一次遗留对象”的假通过风险，因此标准套件要求每次都实例化四个对象、构建不得 rejected，且使用新修订验证证据。旧实验的 console summary 还误用了 `supportOnTable.on` 字段；应读 `supported`。旧实验结果仅用于诊断，不作为验收通过门。
## Studio 用户入口

打开任一已支持世界，在画布右侧“任务过程”选择“准备标准任务场景”。此按钮会经 Skill 权限、WorldIR 编译、准入和 Runtime 事务替换当前场景对象，支持撤销；不会调用生成服务。没有模型服务也能准备和检查场景。

“开始标准任务”每次重新检查当前对象、容器、杯子初始位置、支撑面与合法交互位置；不满足时展示具体原因，不向模型提交必然失败的标准任务。部分执行后使用“重新观察并重试”，不会为重试重置场景或复用旧坐标。准备结果保留实际 `world-provisional`，不会改为 ready。

`tests/studio/standard-task-controls.test.js` 通过真实 Runtime 验证离线准备、权限记录、撤销、缺杯子的启动拦截，以及运动中取杯取消：取杯到安全边界后仍由 agent 持有，任务返回 cancelled，后续放置没有启动。
